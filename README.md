# HPCPerfStats

HPCPerfStats monitors resource usage on HPC systems at multiple levels of resolution and ties it to the jobs that used it.

## Background

HPCPerfStats is the package formerly known as TACC Stats.
It has three components:

| Component            | Build                                                         | Role                                                     |
| -------------------- | ------------------------------------------------------------- | -------------------------------------------------------- |
| `monitor`            | Autotools C daemon, linked against a static dependency bundle | Online data collection and transmission on cluster nodes |
| `hpcperfstats`       | podman-compose stack of 6 services                            | Data curation, analysis and the web site (off-cluster)   |
| `hpcperfstats-tools` | Python setuptools package                                     | Slurm connector, job-efficiency CLI and API client       |

The node daemon `hpcperfstatsd`, installed from the `hpcperfstatsd-3.1-1.el9.x86_64.rpm` package as the systemd service `hpcperfstats`, samples hardware and sends the data to a RabbitMQ server.

The monitor overhead campaign of 2026-11-26 profiled `hpcperfstatsd` 3.1 on 12 node types (3 aarch64, 9 x86_64).
Daemon CPU had a median of 1.59 core-s/h and ranged from 0.823 to 724 core-s/h, or 0.000312% to 0.157% of node capacity.
The highest was on c317-016 (AMD EPYC 7763 64-Core Processor).
The [campaign record](docs/measurements/monitor_overhead_campaign_v31_2026-11-26.md) has the per-node detail, and [Overhead profiles](docs/measurements/overhead_profile/profiles.md) has every metric.

<!-- END generated measurement summary -->

The `hpcperfstats` stack runs 6 services by default: `proxy` (nginx, TLS and the React web UI), `web` (Django and the REST API), `pipeline` (the RabbitMQ consumer, archive, ingest and metrics daemons), `db` (the PostgreSQL database), `valkey` (cache) and `rabbitmq` (the broker the nodes publish to).
`hpcperfstats-tools` runs on a Slurm login node: `hpcperfstats-sacct-gen` loads `sacct` accounting into the site through the API, `hpcperfstats-jobstats` prints a job-efficiency summary, and `ApiClient` is the Python client.
[Architecture](docs/explanation/architecture.md) explains how the pieces fit together.
